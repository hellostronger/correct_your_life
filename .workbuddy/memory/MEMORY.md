# 项目长期约定

## 盈亏汇报口径（2026-11-13 用户明确要求）

- 用户原话：「你要算累计呀，不要算浮亏」。**说个股盈亏时优先给累计总盈亏**
  （已实现 + 浮动），不要只给浮亏；拆解可以附在后面，但结论行必须是累计值。
- 权威口径：`/api/holdings` 的 `total_pnl`（原币）/ `total_pnl_cny`（折人民币）；
  平均成本法实现在 `app.calc_position`，持仓页已有「累计总盈亏(¥)」列。
- 交叉验证：快照报告中若某票基准日 `shares_base=0`，其「相对不动」的 delta
  就等于该票累计盈亏（数学必然，不是巧合）。
- 反事实/归因对比必须口径一致：「纯买入持有浮亏」与「整票累计（含老仓位、
  后续加减仓与做T）」不可直接相减；批次不可分（平均成本法不区分批次）时要明说，
  不要硬拆「某一笔钱」的独立盈亏。
## 账户级真实锚点（2026-11-14 用户要求，后续功能必须联动）

- 账号 2026-09-09 才进 `sa_trades`，之前的本金/盈亏没录入。`account_anchors.py`
  侧车存手填的「真实现金」「总参考收益（账号实际累计总盈亏 ¥）」，
  `/api/account-anchors` 是唯一数据源；**未录入 = None，绝不默认 0**。
- 凡涉及「账户总资产 / 总收益」等绝对金额，必须以这两个锚点为准：
  真实总资产 = 持仓市值 + 真实现金；缺口 = 总参考收益 − 系统已录入累计盈亏。
  系统推算的 `Σ total_pnl_cny` 与快照「推演组合价值（含虚拟现金）」只覆盖已录入流水，
  **只能用于相对量**（差额、胜率、归因），不能当账户真实值。
- 差额、胜率、回本价、归因等相对量/个股口径不受锚点影响，别被联动改写。
- **买卖自动联动（2026-11-14）**：锚点带 `asof_date` 基准日与录入时系统盈亏快照；
  之后报「真实现金」用 `cash_now_cny`（锚点+基准日后净交易现金流+净出入金）、
  报「账号实际总收益」用 `real_pnl_now_cny`（锚点+系统盈亏增量）。
  锚点存储值永不因新交易被改写；`未覆盖缺口` 钉死在录入时点。

- **归因卡逐笔读法**：`score_trades` 把每笔买卖单独对现价打分，一个日内 T 回合会被
  拆成「买腿大负 / 卖腿大正」两条（如 11-11 买 02513 200@501.5 → −¥15,827，
  同日卖 200@504.5 → +¥16,337，配对 +¥510）。用户问「这笔是不是买贵」时，
  必须把同日/紧邻的反向腿一起找出来配对看，别只挑买入那条下结论。
  佐证顺序：当天买/卖股数是否相等、净现金流多少、之后有无更高卖价。
